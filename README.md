## 📌 Problem Statement & Objectives

In safety-critical aerospace and industrial rotating machinery, unplanned failures cause severe operational disruption, emergency repair costs, and safety risks. Conversely, rigid calendar-based maintenance schedules often replace healthy components prematurely.

This project implements a predictive maintenance system on multivariate turbofan engine sensor telemetry to:
1. **Estimate Remaining Useful Life (RUL)**: Accurately forecast remaining operational cycles using ensemble regression.
2. **Detect Early Sensor Anomalies**: Identify subtle sensor drift away from baseline nominal behavior before catastrophic breakdown.
3. **Calculate Early Warning Lead Times**: Measure operational warning windows to support condition-based maintenance planning.
4. **Provide an Interactive Diagnostics Interface**: Enable maintenance engineers to explore fleet telemetry, inspect anomaly progressions, and test custom flight datasets.

## 📊 Dataset & Limitations

The system is trained and benchmarked on the canonical **NASA Commercial Modular Aero-Propulsion System Simulation (C-MAPSS)** dataset (`FD001`):
- **Simulation Conditions**: Sea-level single operational regime.
- **Fault Mode**: High-Pressure Compressor (HPC) degradation.
- **Fleet Size**: 100 turbofan engines simulated from nominal state to run-to-failure breakdown.
- **Sensor Channels**: 21 raw sensor measurements (temperatures, pressures, fan speeds, bypass ratios) and 3 operating settings.

### Dataset Limitations:
- **Simulation vs. Flight Reality**: C-MAPSS data is generated by thermodynamic simulation models; real-world engines experience external weather variability, fluctuating flight envelopes, and diverse maintenance histories.
- **Single Fault Mode (`FD001`)**: The model is trained on compressor degradation. Multimodal failures (e.g., turbine blade cracks or bearing failures in sub-datasets `FD002`–`FD004`) require multi-regime normalization.
- **Run-to-Failure vs. In-Service Censoring**: In `FD001`, each engine runs until catastrophic failure. Real industrial operating data is right-censored because maintenance teams overhaul engines before failure occurs.

## ⚙️ Feature Engineering & Target Formulation

1. **Variance Filtering**: Dropped 7 flat sensor channels with near-zero standard deviation across engine lifespans (`sensor_1`, `sensor_5`, `sensor_6`, `sensor_10`, `sensor_16`, `sensor_18`, `sensor_19`).
2. **Causal Rolling Statistics**: Computed backward-looking rolling mean and rolling standard deviation over a 5-cycle window ($w = 5$, `min_periods=1`) grouped strictly by engine ID (`id`). This guarantees:
   - **No Lookahead Leakage**: Only historical and current cycles are used for feature computation.
   - **No Cross-Engine Leakage**: Grouping by engine ID prevents statistics from bleeding across different engines.
   - **Full Cycle Coverage**: `min_periods=1` allows immediate inference from cycle 1 without dropping early records.
3. **Piecewise Linear RUL Target**: During early cycles, degradation is undetectable. The RUL target is capped at 130 cycles:
   $$\text{RUL}(t) = \min(\text{MaxCycle} - t, 130)$$
   This prevents regressor bias from fitting noise during healthy operating periods.
4. **Final Feature Schema**: 29 input features (14 informative sensors, 3 operating settings, 12 rolling statistics).

## 📈 Model Evaluation & Reproducible Benchmarks

All models were evaluated on strictly separated held-out test engines (20 engines, 4,070 cycles, `test_size=0.2, random_state=42`) with zero engine-level leakage and identical RUL target formulation. Learned transformations (e.g., standard scaling) were fit strictly on the 80 training engines.

### Prognostic Regression Benchmarks (Held-out Test Fleet, Cap = 130)

| Model Architecture | Features & Preprocessing | RMSE | MAE | R² | Operational Role |
| :--- | :--- | :---: | :---: | :---: | :--- |
| **Naive Mean Baseline** | Constant train target mean (88.87) | 43.47 | 38.54 | -0.00 | Naive baseline; predicts constant average life |
| **Linear Regression** | Standardized (fit on train), clipped $\ge 0$ | 20.93 | 16.69 | 0.77 | Simple ML baseline; underfits nonlinear degradation stages *(unconstrained: 21.17 RMSE / 17.03 MAE)* |
| **Random Forest Regressor** | 200 Estimators, raw features, clipped $\ge 0$ | **17.98** | **12.92** | **0.83** | Production regressor; ~14% error reduction over linear baseline *(native NaNs: 17.90 RMSE / 12.85 MAE)* |

### Unsupervised Anomaly Detection Benchmarks (Isolation Forest)

The Isolation Forest detector was trained on healthy operating regimes (`RUL > 100`) with 200 estimators and 5% contamination. Because run-to-failure datasets lack human-annotated discrete fault injection timestamps, performance is evaluated across operational regimes:

| Evaluation Metric | Target Operational Regime | Score / Rate | Interpretation |
| :--- | :--- | :---: | :--- |
| **False Alarm Rate (FAR)** | Nominal Cycles ($RUL > 100$) | **5.71%** | 117 false alarms out of 2,050 nominal cycles (aligns with 5% contamination) |
| **Detection Recall** | Critical Degraded Phase ($RUL \le 30$) | **100.00%** | 620 out of 620 degraded cycles flagged before functional failure |
| **Extended Recall** | Degraded Phase ($RUL \le 50$) | **94.41%** | 963 out of 1,020 cycles flagged |
| **First-Trigger Lead Time** | Fleet Test Units (20 engines) | **Median: 188.5** (Mean: 187.1) | Earliest isolated detection cycle prior to failure [Min: 46, Max: 268] |
| **Sustained 3-Cycle Lead Time** | Fleet Test Units (20 engines) | **Median: 66.5** (Mean: 92.2) | 3 consecutive anomalous cycles filtering out nominal noise [Min: 36, Max: 268] |

> [!NOTE]
> **Audit Finding on Model Provenance & Training Split Integrity**:
> - **Supervised RUL Regressor (`rul_model.pkl`)**: **Verified Independent**. The Random Forest model artifact was verified to have been trained strictly on the 80 training engines (`random_state=42`, Cell 20/26 of `Anamoly_Detection.ipynb`), ensuring zero cross-engine group leakage on the 20 held-out evaluation engines. Native-NaN evaluation reproduces the exact historical training notebook metrics (17.90 RMSE / 12.85 MAE / 0.8304 R²), while zero-imputed production evaluation yields 17.98 RMSE / 12.92 MAE / 0.8288 R².
> - **Unsupervised Anomaly Detector (`anomaly_model.pkl`)**: **Disclosed Limitation**. In `Anamoly_Detection.ipynb` (Cell 31), nominal cycles (`RUL > 100`) were selected from the complete 100-engine dataset prior to engine-level splitting. Consequently, nominal baseline telemetry from the 20 evaluation engines was present during Isolation Forest fitting. Retraining the detector on a strictly isolated 80-engine split is recommended for defensible zero-leakage production certification.
> - **Lead-Time & Ground Truth Semantics**: The previously cited "~40–46 cycles lead time" was an anecdotal single-engine observation (Engine 1 = 43 cycles). Across the full 20-engine test fleet, isolated anomaly triggers occur early due to the ~5.7% false alarm rate in nominal cycles (median 188.5 cycles). Requiring **3 consecutive anomalous cycles** filters early false alarms and yields a reliable median early warning window of **66.5 cycles** before breakdown. Because C-MAPSS FD001 lacks discrete fault injection timestamps, operational regimes ($RUL > 100$ vs $RUL \le 30$ / $RUL \le 50$) serve as evaluation proxies; 100% degraded recall reflects continuous abnormal sensor drift, not discrete real-world failure prediction.

## 🚀 Quick Start Guide

### 1. Prerequisites
- **Python**: Version 3.10, 3.11, or 3.12 recommended.
- **Git & Git LFS**: Ensure Git Large File Storage is installed ([git-lfs.github.com](https://git-lfs.github.com/)).

### 2. Clone the Repository & Pull Model Artifacts
```bash
git clone https://github.com/Vedant04-tech/nasa-turbofan-predictive-maintenance-ai.git
cd nasa-turbofan-predictive-maintenance-ai

# Initialize Git LFS and download serialized model files
git lfs install
git lfs pull
```

### 3. Set Up Virtual Environment
```bash
# On Linux / macOS:
python3 -m venv .venv
source .venv/bin/activate

# On Windows (PowerShell):
python -m venv .venv
.venv\Scripts\Activate.ps1
```

### 4. Install Dependencies
```bash
# Production runtime:
pip install -r requirements.txt

# Development and testing tools:
pip install -r requirements-dev.txt

# (Optional) Install the turbofan_ai package in editable mode:
pip install -e .
```

### 5. Launch the Dashboard
```bash
streamlit run app.py
```

1. Open your browser at `http://localhost:8501`.
2. Choose **"Load Benchmark Sample Dataset"** for instant demonstration or **"Upload Custom CSV"** to test your own data.
3. Select an Engine Unit ID and interactively adjust the **Anomaly Sensitivity Threshold** slider to evaluate risk shifts.

### 6. Run Reproducible Evaluation Benchmark
To independently reproduce all regression metrics and anomaly detection benchmarks on the held-out test fleet:
```bash
python scripts/evaluate.py
```
This generates:
- `reports/metrics.json`: Full machine-readable metrics, split seeds, and audit metadata.
- `reports/actual_vs_predicted.png`: Actual vs. predicted scatter plot with identity reference lines.
- `reports/residuals.png`: Residual error histograms and actual vs. residual plots.
- `reports/anomaly_progression.png`: Anomaly score degradation profiles across representative test engines.

## 🔒 Known Limitations & Future Work

1. **Deep Learning Sequence Modeling**: Replacing flat rolling features with temporal deep learning architectures (e.g., Temporal Convolutional Networks [TCN] or BiLSTM/Transformers) to learn degradation trajectories over varying sequence lengths.
2. **Multi-Condition Normalization**: Extending preprocessing pipelines to C-MAPSS sub-datasets `FD002` and `FD004` that feature 6 operating conditions and multiple failure modes.
3. **Uncertainty Quantification**: Incorporating Conformal Prediction or Quantile Regression Forests to output calibrated confidence bounds around RUL predictions ($RUL \pm \delta$) for safety-critical maintenance decisions.
4. **API Serving**: Exposing FastAPI endpoints with OpenAPI specifications for headless microservice deployment in Kubernetes environments.
